Frame generation explained: smoother, but at what cost?

Published by AdStern, Vienna

Reviewed November 2, 20264 min readHow we check pages

Frame generation can roughly double the frame-rate counter with one switch. It does not make the game react faster, though: the extra frames are generated between rendered ones, and the game still responds at the rendered rate – plus a little extra delay. Used at the right base frame rate it makes motion clearly smoother; used to rescue a struggling system it often feels worse than it looks.

How frame generation works

A game normally renders every frame you see. With frame generation, the GPU renders a frame, then creates one or more additional frames that sit between two rendered ones in time. The generated frames are estimated from the two neighboring frames and from motion information the game provides, such as motion vectors and depth.

To place a generated frame between two rendered frames, the newer rendered frame has to be held back until the generated one has been shown. That holding back is the reason frame generation adds latency. It is also why games that offer frame generation usually also offer a latency-reduction feature – NVIDIA Reflex, AMD Anti-Lag 2 or a similar option – and why NVIDIA requires Reflex to be active with DLSS Frame Generation.

Which versions exist

DLSS Frame Generation from NVIDIA runs on GeForce RTX 40 series and newer cards; the RTX 50 series adds Multi Frame Generation, which can insert more than one generated frame per rendered frame. AMD FSR Frame Generation (introduced with FSR 3) is designed to run on a wide range of graphics cards from different vendors. Some games also have their own implementations, and tools such as Lossless Scaling offer frame generation that works outside the game, with less information about the scene and usually more visible artifacts.

Exact requirements change with new versions and drivers, and each game decides which versions it supports. Check the game’s settings menu and the vendor pages listed below for your card.

The three costs: latency, artifacts, memory

Latency. Because the newest rendered frame waits, the time from your input to the screen grows slightly compared with the same base frame rate without generation. Latency reduction features recover part or all of that, depending on the game and system. The practical rule is simple: the game will feel roughly like its rendered frame rate, while it looks like the generated one.

Artifacts. Generated frames are estimates. Fast-moving objects, transparent effects, user-interface elements and text can show smearing or flicker, especially when the base frame rate is low and the gap between rendered frames is large.

Memory and GPU time. Generation needs extra video memory and some GPU time. On cards with little VRAM this can push memory use over the limit; on a fully loaded GPU it lowers the rendered frame rate a little before doubling it.

The base frame rate decides everything

Rendered FPS before generationDisplayed FPSTypical experience
Below about 30Below about 60Usually not recommended: visible artifacts and sluggish response
About 40–50About 80–100Acceptable in slower games; fast action can feel delayed
About 60 and aboveAbout 120 and aboveThe intended use: very smooth motion, latency close to normal
Already at the display’s refresh rateCapped by refresh rateLittle benefit; extra frames may be discarded or need a cap

Thresholds are broad, commonly cited guidance – not measurements. Vendors themselves recommend a solid base frame rate.

Frame generation multiplies what is already there. At 60 rendered frames per second it can turn a smooth game into a very smooth one on a high-refresh display. At 25 rendered frames per second it produces 50 frames that still react like 25 – and with more visible errors because each estimate has to bridge a longer gap.

How to set it up

  • First get a good base frame rate with normal settings and an upscaler mode – frame generation is the last step, not the first.
  • Turn on the latency reduction option the game offers (it is often switched on automatically).
  • Use a display with variable refresh rate (G-Sync, FreeSync or HDMI VRR) if you can. The generated frame rate should stay within its range.
  • Avoid running above the display’s refresh rate: follow the game’s or driver’s recommendation on V-Sync and caps for frame generation.
  • Compare with and without in the same scene – how it feels while turning the camera quickly matters more than the counter.

When to turn it off

Turn frame generation off in competitive multiplayer games where reaction time decides, when the base frame rate is low, when you see distracting artifacts in the interface, or when video memory is already full. Turn it on for single-player games on a high-refresh display when the base frame rate is already good and you want smoother motion. After a game update, re-check it: patches often update the frame generation version or fix (or introduce) artifacts.

Frequently asked questions

Does frame generation increase input lag?

Slightly, compared with the same rendered frame rate without it, because the newest frame is held back. Latency reduction features such as NVIDIA Reflex or AMD Anti-Lag 2 recover part of it.

What base frame rate do I need for frame generation?

There is no fixed number, but it works best when the game already runs at around 60 rendered frames per second or more. Below about 30 it usually looks and feels poor.

Does frame generation work with V-Sync?

It depends on the version and the game. Follow the game’s recommendation; with a variable refresh rate display, keep the output frame rate within the display’s range.

Should I use frame generation in competitive games?

Usually not. Reaction time follows the rendered frame rate, and the small extra delay works against you.
